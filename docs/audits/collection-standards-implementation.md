# Collection Standards Implementation

Trusted collection follows one fixed order: open the official source, confirm Canada scope, apply or document the source sort policy, paginate, extract, normalize and deduplicate, score locally, then save and report. Post-collection Canada rejection is a safety gate, not a replacement for source scoping.

## Default Policy

- Standard production and verification sources use a 20-page cap.
- The collector requests a public `Most Recent`, `Date Posted`, `Newest`, or equivalent control before pagination when one is available.
- Every run reports the requested and used sort, its status, method, and reason.
- Every run reports page policy, target cap, pages scanned, jobs per page, stop reason, completion state, and whether an engineering follow-up is required.
- Reaching a page cap is partial by definition. It never represents complete source traversal.

## Exceptions

- Scotiabank: `all_available` pages after Canada scope. Its public board has no usable newest-first control, so it records `sort_status: unavailable_by_source` and stops only at the real end of the listing, a duplicate page, a blocker, or the 500-page defensive ceiling.
- Cognizant: uses the same `all_available` policy and source-order reporting as Scotiabank.
- RBC: production remains capped at 20 Canada-scoped pages. Its audit-only policy is 75 pages and requests newest-first before pagination.

## Completion Semantics

`no_more_pages` and `next_disabled_or_missing` are normal completed endings. `max_pages_reached` means a capped run may be incomplete. `duplicate_page_detected`, `pagination_control_failed`, `scope_not_confirmed_before_pagination`, `sort_not_confirmed`, `safety_ceiling_reached`, and browser barriers are reported as incomplete or requiring review.

## Audit Practice

Manual URL recall is always compared with the scored-candidate export generated by the fresh diagnostic run. It is never inferred from an older export or from saved jobs alone.
